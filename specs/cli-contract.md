# Native CLI Machine Contract

## Scope

- This document freezes the v1 machine-readable contract for the planned native CLI.
- The contract is route-neutral: it does not assume a Go, Rust, or Node implementation as long as the observable CLI behavior stays identical.
- Script and CI usage are the primary target. Human-readable output may exist, but only machine mode is covered by this stability guarantee.

## Command Naming Rules

- The runtime binary is referred to here as `<native-cli>` because the implementation language and final binary name are not yet fixed.
- Public command ids use a flat kebab-case namespace: `^[a-z][a-z0-9-]*$`.
- The current MCP inventory in `.sisyphus/specs/migrate-mcp-client-to-native-cli/parity-matrix.json` is the migration source of truth for capability coverage.
- The default mapping rule from current MCP tools to native commands is mechanical:
  - remove the `gemini_` prefix
  - replace `_` with `-`
- Examples:
  - `gemini_send_message` -> `send-message`
  - `gemini_download_full_size_image` -> `download-full-size-image`
  - `gemini_browser_info` -> `browser-info`
- New commands added after parity freeze must also follow flat kebab-case and must not reuse an existing command id with changed behavior.

## Stable Global Flags

| Flag | Meaning | Contract notes |
| --- | --- | --- |
| `--json` | Enable machine-readable mode. | In v1 this is the only stable output mode for scripts and CI. |
| `--timeout-ms <integer>` | Override the command timeout budget in milliseconds. | The effective timeout must be echoed in `execution.timeoutMs`. |
| `--request-id <string>` | Caller-supplied opaque id. | Echoed back as `requestId`; if omitted, the CLI must generate one. |
| `--help` | Print help for humans. | Human mode is not contract-stable. |
| `--version` | Print CLI version for humans. | Human mode is not contract-stable. |

## Machine Mode Envelope

Machine mode emits exactly one JSON document to stdout and optionally one trailing newline.

### Required top-level shape

```json
{
  "schemaVersion": 1,
  "mode": "json",
  "command": "send-message",
  "requestId": "req_20260328_01",
  "ok": true,
  "exitCode": 0,
  "timing": {
    "startedAt": "2026-03-28T10:00:00.000Z",
    "finishedAt": "2026-03-28T10:00:18.542Z",
    "durationMs": 18542
  },
  "execution": {
    "timeoutMs": 60000,
    "terminalState": "succeeded",
    "cancelledBySignal": null
  },
  "result": {
    "text": "Gemini is a conversational AI system for text and image workflows.",
    "responseIndex": 0,
    "artifacts": []
  },
  "error": null
}
```

### Field rules

| Field | Type | Rules |
| --- | --- | --- |
| `schemaVersion` | integer | Fixed to `1` for this contract. |
| `mode` | string | Fixed to `json` in machine mode. |
| `command` | string | Canonical kebab-case public command id. |
| `requestId` | string | Non-empty; caller-supplied or generated by the CLI. |
| `ok` | boolean | `true` on success, `false` on terminal failure. |
| `exitCode` | integer | Mirrors the process exit code used by the CLI. |
| `timing.startedAt` | string | ISO-8601 timestamp in UTC. |
| `timing.finishedAt` | string | ISO-8601 timestamp in UTC. |
| `timing.durationMs` | integer | Non-negative wall-clock duration in milliseconds. |
| `execution.timeoutMs` | integer or `null` | Effective timeout budget for the invocation. |
| `execution.terminalState` | string | One of `succeeded`, `failed`, `timed_out`, `interrupted`. |
| `execution.cancelledBySignal` | string or `null` | Signal name such as `SIGINT` when interrupted. |
| `result` | object or `null` | Command-specific success payload. Must be `null` on failure. |
| `error` | object or `null` | Failure payload. Must be `null` on success. |

### Error object

```json
{
  "category": "timeout",
  "code": "timeout",
  "message": "Command exceeded timeout while waiting for Gemini to finish responding.",
  "retryable": true,
  "details": {
    "phase": "wait-for-response",
    "elapsedMs": 10000
  }
}
```

Rules:

- `error.category` must use one of the categories listed in `exit-codes.json`.
- `error.code` is the stable machine token for the failure and equals the category unless a later version documents a narrower subtype.
- `error.message` is human-readable but still safe to expose in JSON mode.
- `error.details` must remain JSON-serializable and must not contain log spam or incremental progress output.

## Stdout And Stderr Split

- In machine mode, stdout is reserved for the final JSON envelope only.
- No banners, polling updates, spinner frames, selector traces, daemon lifecycle logs, or warning text may be mixed into stdout.
- All diagnostics, progress updates, and recovery hints belong on stderr.
- This supersedes the current MCP-specific stdout guard in `src/mcp-server.js`; the native CLI must preserve the same machine-clean property without relying on JSON-RPC framing.
- The current polling pattern in `src/demo2.js` (`polling... status=...`) is only acceptable on stderr in native CLI machine mode.
- On failure, the JSON error envelope still goes to stdout; supplemental human-readable diagnostics may go to stderr.

## Timeout And Cancellation Semantics

- v1 machine mode is terminal-only: long-running commands block until they succeed, fail, time out, or are interrupted.
- There is no progress-stream contract on stdout in v1.
- If `--timeout-ms` is reached before a command finishes:
  - process exit code is the `timeout` exit code from `exit-codes.json`
  - `ok` is `false`
  - `execution.terminalState` is `timed_out`
  - `execution.timeoutMs` records the effective budget
  - `error.category` is `timeout`
- If the command is interrupted by `SIGINT`, `SIGTERM`, or an equivalent cooperative cancellation path:
  - process exit code is the `interrupted` exit code from `exit-codes.json`
  - `ok` is `false`
  - `execution.terminalState` is `interrupted`
  - `execution.cancelledBySignal` records the signal when known
  - `error.category` is `interrupted`
- If the process is hard-killed before it can print the JSON envelope, that is outside the CLI contract and must be treated by callers as a transport-level failure rather than a contract-compliant command result.

## Exit Codes

- The stable exit-code mapping lives in `.sisyphus/specs/migrate-mcp-client-to-native-cli/exit-codes.json`.
- Machine mode must keep `exitCode` in the JSON envelope equal to the real process exit code.
- Unknown failures must map to `internal-error`; implementations must not invent ad hoc exit codes without updating the table first.

## Compatibility Reporting Shape

Later migration tasks must record compatibility impact per command or capability using the template in `compatibility-impact-template.md`. The record should carry the following data shape even if it is stored as Markdown instead of raw JSON:

```json
{
  "schemaVersion": 1,
  "legacyTool": "gemini_send_message",
  "nativeCommand": "send-message",
  "capabilityGroup": "model-and-conversation",
  "impactLevel": "compatible",
  "inputChanges": [],
  "outputChanges": [],
  "behaviorChanges": [],
  "stdoutContract": "json-only",
  "stderrContract": "diagnostics-only",
  "timeoutAndCancel": "unchanged",
  "exitCodeCoverage": ["timeout", "interrupted", "internal-error"],
  "evidence": [
    "src/mcp-server.js:244",
    ".sisyphus/specs/migrate-mcp-client-to-native-cli/parity-matrix.json"
  ]
}
```

Impact levels are:

- `compatible`: no externally visible machine-contract break.
- `minor`: additive or operationally meaningful change without breaking the baseline parser.
- `breaking`: caller-visible incompatibility requiring migration work.
- `deferred`: capability intentionally not delivered in the current milestone.

## Notes Tied To Current Repo Behavior

- Most public commands share the current runtime chain `src/mcp-server.js` -> `src/index.js:createGeminiSession()` -> `src/browser.js:ensureBrowser()` -> `src/gemini-ops.js`.
- `browser-info` is the exception and talks to daemon HTTP endpoints directly; it still must emit the same envelope and use the same stdout/stderr split.
- Login prechecks for image generation, daemon auto-start, local file writes, and timeout-sensitive waits are observable behaviors that later compatibility reports must track.
